# ChatDaily 独立重写规格审查记录

日期：2026-09-27。产物是 [独立规格包](../../rewrite/README.md)，覆盖 24 项能力及 52 个验收场景。规格已具备启动独立实现的业务、接口、状态和迁移依据；新程序的实现、测量和发布分别在后续阶段验收。

## 审查依据

[源码映射](source-map.md) 对应当前含未提交改动的工作树，精确文件 hash、符号及行号保存在 [source-map.json](source-map.json)。审查覆盖源码目录的模块清单、公开 CLI、配置、调度、SQLite 与账本接口、静态定时页面以及相关历史报告；未把 Git HEAD 当作全部现状。

[现场观察](observations.json) 记录本机配置的非秘密字段和产物类型。2026-09-26 的归档存在简报、核验、视觉、健康和阶段标记；本机配置启用了多项可选能力，L2 请求模式仍为 report、enforce 关闭。观察仅包括本机文件与配置，没有远端版本验证或 Telegram 读回，不能据此重判生产发布结果。

保留的历史证据包括 [2026-09-08 性能报告](../../../acceptance-report-refactor-20260908/report.md)、[来源链路性能报告](../../../acceptance-report-source-performance-final/report.md) 和 [微信真实数据运行报告](../../../acceptance-report-wx-production-yesterday/report.md)。原始数据、撤回的 SQL 实验、失败与复审记录保持原样。旧局部加速结果没有被写成新项目目标或生产吞吐。

## 主要问题与规格决定

| 审查问题 | 对重写的影响 | 规格中的决定 |
|---|---|---|
| 只按 README 盘点会遗漏机会、成长反馈、健康、知识发布、意图和信号监控 | 新系统上线后才发现原工作流消失 | F01–F24 全量能力与 AT 映射；已门控、实验和新目标各自标注 |
| `seen`、完成标记与真实送达含义混合 | 误发、漏发、歧义伪装成功 | [身份与状态](../../rewrite/03-domain-and-delivery.md) 区分采集、计划、attempt、confirmed、suppressed、ambiguous |
| 部分正文/媒体恢复缺少完整部件回执 | 文本重生成或恢复可能重复媒体 | 冻结内容义务与允许替代分支，保留所有部件回执和内容修订 |
| 抓取限额、软失败空洞、跨来源顺序影响完整性和筛选 | 加速可能靠漏抓、排序改变去重结果 | 覆盖区间与空洞可追踪；分页、公平性和排序策略纳入 AT |
| `--no-push` 的局部无发送被误读成全流程只读 | 预览消费反馈、更新 rubric | 分开只读检查、生成不发送、正式运行和历史回放 |
| 数据库 fencing 不能阻止持有凭据的旧进程发送 | 切主后双投递 | 在发送出口或旧执行环境隔离，AT38 观察真实发送边界 |
| 只恢复旧快照的回滚方案 | 丢失切换后回执、反馈与配额 | 增量事实前向合并；新系统已发送后也必须能演练回滚 |
| 将技术选择写成产品约束 | 重写继续复刻旧结构 | 语言、库、队列、模型与框架按条件选择；只固定业务结果与外部兼容合同 |
| 旧知识材料中 metadata/source_only 容易被误删 | 已有缓存和出处减少 | 保留记录角色；机会库直收与访问范围过滤明确列为新增目标 |
| 只写“更快”“架构更好” | 无法判断重写是否成功 | 固定合成负载、完整性、分阶段时延、资源与发布门 |

详细要求分别留在规格的职责文档中；本表只记录审查结论。

## 独立复审

两路 GPT-6 Sol（high）分别盘点与复核投递来源、成长知识能力；GPT-6 Astra（high）独立复核状态、架构、迁移和验收。成稿复审指出的 15 项实质问题均已修订，并针对原问题复验闭合。复审结论针对规格合同，不计作新程序测试结果。

## 现有文档修正

README 增加规格入口，并把易变的成长模型名称改为 wrapper/config 查询入口。ARCHITECTURE 修正 `claim_next`、评审模型配置和周报 marker 的当前实现。runbook 说明 delivered/ambiguous 周标记、无推送模式副作用及消费后的反馈历史，同时修正公开频道补发的 Python 模块入口。

旧报告、程序、生产配置、调度和远端文件未修改。代码引用集中在本过程目录；独立规格包不依赖仓库外的文件或旧实现。

## 验证与分发

验证结果见 [validation.json](validation.json)：本地链接与锚点、F/AT 双向覆盖、JSON 与样例 hash、旧输入 schema、源码符号、许可证、分发清单，以及旧工作树非文档文件的校验。

已运行公开 CLI、成长周报和频道补发的 `--help` 检查，确认现有命令和参数存在；未运行会读取业务数据、调用模型或发送消息的命令。52 个 AT 是新程序的待执行用例，不是此次运行了 52 个测试。

可分发文件为 [chatdaily-rewrite-spec-1.0.zip](chatdaily-rewrite-spec-1.0.zip)，仅包含独立规格目录。解压后可按其中 MANIFEST.sha256 校验；包内不含旧代码、过程记录、真实消息或密钥。代码实现从 [启动说明](../../rewrite/IMPLEMENTATION_BRIEF.md) 开始。
