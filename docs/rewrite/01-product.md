# 产品范围

## 目标与读者

产品服务于自行管理消息源和 Telegram 目标的个人使用者与运维者。它减少逐群阅读、重复转发和资料失散，同时保留回到来源、复查筛选决定、恢复失败任务的能力。

重写要达成四个结果：功能有可核验的覆盖清单；数据和外部投递状态有明确归属；失败可定位和恢复；新增来源或替换模型不需要修改所有管线。技术栈更换本身不作为成功指标。

## 用户工作流

| 工作流 | 用户得到的结果 | 功能合同 |
|---|---|---|
| 配置来源和目标 | 可验证的来源范围、主题路由、模型能力与调度计划 | [F01](02-capabilities.md#f01)、[F18](02-capabilities.md#f18) |
| 看日报 | 指定日期的简报、详细稿、来源与风险记录 | [F02–F05](02-capabilities.md#f02)、[F12](02-capabilities.md#f12)、[F15](02-capabilities.md#f15) |
| 看原文与订阅 | 原频道消息、相册、视频和文章卡片，含来源入口 | [F06–F11](02-capabilities.md#f06) |
| 复习个人成长内容 | 有原文切片的日卡、反馈与周报 | [F13–F14](02-capabilities.md#f13) |
| 查旧资料 | 带来源与时间的搜索结果、可解释的索引状态 | [F16–F17](02-capabilities.md#f16) |
| 处理故障与迁移 | 知道哪里失败、哪些已发、哪些待确认，并定向恢复 | [F07](02-capabilities.md#f07)、[F19–F22](02-capabilities.md#f19) |
| 接收特定频道信号 | 符合确定性条件的及时提醒 | [F23](02-capabilities.md#f23) |

## 功能地位

- **替换必需**：F01–F14、F18–F20、F22 的业务能力。可选功能保留开关；替换必需不等于必须全部启用。
- **已有可选能力**：F05、F13–F15、F23。接管启用了该功能的运行配置时必须完成该项；不能默认关闭以宣称功能对齐。
- **已有受门控能力**：F16 的知识检索与发布、F17 的意图反馈存储。保留数据和已实现操作；是否开放普通查询、是否接入聊天助手属于独立发布决定。F16 的机会库直接收录及跨访问范围过滤是另行验收的新扩展。
- **新界面目标**：F21 中的运维网页。当前能力基线只有定时设计器；完整控制台属于新实现设计，不得宣称已存在。CLI 先行，网页可后续交付。
- **实验与兼容遗留**：F24。保留有价值的评测与数据导出，不强制重做实验脚本、废弃图床或旧内部调用入口。

类别可重叠：例如 F05 需要保留可选能力，在未启用 vision 的部署中可以不安装相关依赖。每个迁移 profile 列出启用的 F 编号；未迁移项继续由明确的旧写入者负责。

## 不扩大的范围

本规格不要求重写微信客户端、tg-cli、模型网关、X Monitor、Podcast4Bot、健康采集器或通用任务监控系统。它们通过 [接口合同](04-integrations.md) 接入。也不预设多租户 SaaS、收费账户系统、公开内容门户、无限网页爬取或通用聊天 Agent。

新增原生来源、向量数据库、浏览器自动化或常驻后台服务时，说明它解决的当前缺口。不能把一个既有 CLI 临时故障直接解释为必须重做整套上游。

## 交付顺序

| 阶段 | 可交付结果 | 进入下一阶段的条件 |
|---|---|---|
| M0 合同与骨架 | 配置校验、合成来源、持久状态、模拟发送、诊断 CLI | 身份、崩溃、部分发送、歧义与重放用例通过 |
| M1 第一条真实链路 | 一个测试来源到一个测试 Telegram 目标，含归档和恢复 | 真实回执可读回，生产写入仍由旧系统负责 |
| M2 核心功能对齐 | 日报、原文频道、B站/YouTube、机会与去重、调度、外部 ledger | 必需功能用例、性能负载、导入演练通过 |
| M3 配置能力对齐 | 成长、健康、知识与反馈、信号监控；CLI 完整，网页至少只读 | 启用项逐项有证据；未开放的实验仍有明确开关 |
| M4 按管线接管 | 影子对比、切换写入者、真实定时周期、故障恢复、回滚演练 | [生产接管门](09-acceptance.md#release-gates) 满足 |
| M5 界面与旧系统收口 | 写操作网页、旧任务退役和保留数据导出 | 新界面用例通过；保留期与回滚窗口有记录 |

每个阶段都能运行。可以按管线提前切换已完成的范围，但整个重写只有在覆盖表所有项有实现、保留或明确退役决定后才算完成。

## 兼容与改进

业务目标是来源完整、内容可信、低噪声投递、失败可恢复。旧系统的静默截断、混合 `seen` 语义、模型名硬编码、重复执行导致计数变化和预览副作用均不作为兼容要求。迁移这些历史状态时保留原始事实，不能用新含义重写历史证据。

[决策登记](10-decisions.md) 列出必须在生产接管前解决的选择。这些问题不阻塞合成数据开发，也不能被实现者悄悄当作已获确认的业务变更。
