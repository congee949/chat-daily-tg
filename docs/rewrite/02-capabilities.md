# 功能合同

每节是一个可以独立追踪的能力。正常输出、失败行为与范围共同构成合同。具体状态含义统一引用 [领域与投递状态](03-domain-and-delivery.md)，接入字段统一引用 [外部接口](04-integrations.md)，不以旧函数签名约束新实现。

<a id="f01"></a>
## F01 配置、身份、目标与模型

配置来源、启停状态、过滤策略、目标话题、时间范围、保留规则与模型能力。来源使用平台稳定 ID，名称只作展示；同名来源不得串档。配置加载先校验引用、类型、范围和必需能力，未知字段应报告，不能静默忽略关键拼写错误。

只启用原文转发时，不要求无关摘要模型。密钥用引用注入，不进入配置导出、前端或日志。路由使用稳定业务键，执行时保存解析后的目标快照。找不到路由时，仅可回落到明确配置且权限合适的目标；无法确定安全目标就保持待处理并告警。配置预览显示差异，生效后可查询版本。

<a id="f02"></a>
## F02 微信来源

从已有的合法本地访问工具读取选定群、日期范围、发送人、原文、消息 ID 和可取得的附件。逐来源隔离失败，保留来源时间与采集时间、导出完整性状态和截断原因。

成功导出不能被一次空文件、冷启动未完成或失败响应覆盖。附件缓存应验证身份；命中缓存可减少重复读取。图片失败仍保留消息与可恢复定位。访问工具不可用时报告源故障，不尝试绕过系统权限或改变客户端签名。

<a id="f03"></a>
## F03 Telegram 日报来源

读取选定聊天在指定时区下的半开时间窗 `[start, end)`。支持发送人排除、关键词白名单和整条排除；这些规则与 F06 原文转发配置分开。

可直接读已有本地记录，或显式同步后读取。分页直到覆盖窗口或用尽预算；预算不足必须记录未覆盖区间和继续入口。旧实现的“只取最新 limit 条”属于已知完整性缺口，新实现不能静默沿用。正文、caption、来源链接和媒体候选共同进入归档；同步失败与确实无消息分别显示。

<a id="f04"></a>
## F04 日报生成与归档

默认生成上一业务日，也能指定日期、重新生成独立版本和恢复未完成投递。输入为 F02/F03 原文、可用视觉说明、活跃机会、近期热点及可用证据。按来源保留原始材料、初稿、简报、详细稿、核验结果和事实风险记录。

输出应说明主要信息、条件、时间与来源，去除模型思考标签、无来源断言和无效引用。摘要与核验分阶段；核验失败时可降级为标明未完成核验的初稿。结构错误需解析、归一化及有界修复，仍无可用正文则失败并保留材料。有效性基于内容合同；旧字符数下限不成为所有语言和场景的永久规则。

正常生成后按 F07 投递，保留长文回落及图片。所有来源已覆盖且没有合格内容时返回 `no_content`；所有来源失败时返回采集失败，不能把未取得数据当作空内容。两者都不写“已送达”。按来源显示缺口，部分来源失败允许生成带覆盖说明的简报。重新生成不得自动重发已经确认的版本。

<a id="f05"></a>
## F05 图片理解与富内容

在启用时识别合格图片、排除低信息图、控制下载大小与数量，对图像说明保留源 ID、模型与策略版本。引用标记仅能指向本轮存在的图片，重复引用去重，无效引用删除并记录。

下载、解析、视觉服务、卡片渲染或富消息失败时正文继续。优先使简报易读，默认少图，详情保存在归档。迁移已有视觉策略时沿用 [兼容 profile](08-migration.md#compatibility-profile)，更换模型或阈值需要重新测量。图床不是必需设施；私有附件不能为实现预览而默认公开上传。

<a id="f06"></a>
## F06 频道原文投递

按来源和目标读取增量消息，支持公开文本卡、私有媒体、纯媒体、相册与长 caption。展示来源名、时间、原帖链接及内容；可选择外部正文链接作预览，同时保留原帖入口。

行级清理只删命中行，整帖排除须记录理由。正常原文路径无需 LLM；语义去重是独立增强。相册优先使用上游分组元数据；缺失时采用可解释的保守分组，不能合并两条各自带正文的帖子。记录所有源成员和目标消息 ID。

媒体无法取得时，可发送有正文或可访问来源入口的占位说明；私有纯媒体若既无正文也无法提供有效来源定位，保留待恢复并告警，不发空卡。部分媒体丢失记 `degraded`，不伪装完整交付。正常就绪项按源时间和 ID 排序；默认允许后续项越过失败空洞继续，恢复时注明原时间。需要严格顺序的 profile 会阻塞同源后续项，其他来源继续。跨来源一般无全序要求；启用 first-arrival 类去重时，先固定批内稳定排序与平局键，或使用不依赖到达顺序的选择规则，并记录胜出依据。补发能定向处理公开文本、私有媒体和整组相册，先展示将重复的部分，再创建显式新投递。

<a id="f07"></a>
## F07 投递与恢复

支持文本、富文本、可用的富消息、图片、视频、动画、文件和相册。格式失败降级，超长内容按稳定计划分段，主文与可选图片分开记录。所有业务共享 [投递状态合同](03-domain-and-delivery.md#delivery-state)，状态查询包含实际目标和回执。

一个任务失败不得阻塞其他管线。明确可重试的失败受次数和截止时间约束；发送不确定进入复核队列。人工恢复保留原尝试，不能靠删除所有 `seen` 或回滚高水位恢复。正文送达后增强存储失败不得触发重复正文。

<a id="f08"></a>
## F08 内容级去重与过滤

支持消息身份、精确正文、规范化 URL、媒体特征及可配置的跨来源规则。URL 规范化保留身份参数；同 URL 的评论或新增事实不得仅因链接相同就自动丢弃。仅在明确启用对应规则并满足其证据条件时抑制。

每条规则有版本、范围、优先级、期限、原因与可恢复的输入引用；相同来源重放与跨来源内容相似分开处理。每频道可以关闭内容/话题去重，但投递幂等仍生效。过期或损坏的外部索引退出判定，保持正文可投递。旧“URL first”策略作为可迁移配置保存，不强制成为新项目全局默认。

<a id="f09"></a>
## F09 同事件判断与人工复核

对确认送达的候选检索、重排并判断是否同事件、是否有新增信息。仅相似不能推出重复。无可靠结论继续投递；小幅新增可附前文链接，实质新增单独投递；有图片的帖子不能只靠 caption 判定全帖重复。

支持 `report`、`annotate`、`enforce`，请求模式与有效模式分别显示。覆盖率、索引时效、向量代际、评测结果、人工确认或调用预算不满足时降级。report 记录假设动作，实际投递不受抑制。抑制决定与审计记录一起持久化，审计失败则不能按该决定终态丢弃。

保持已有人工门槛的语义，详见 [兼容 profile](08-migration.md#compatibility-profile)。机器标签、冻结样本行数与接口成功不计作人工确认。主判定器与 fallback 按能力配置，不能因替换供应商自动继承旧阈值和批准状态。

<a id="f10"></a>
## F10 Bilibili 视频与专栏

按 UID 白名单/黑名单读取订阅；展示名改变不改变身份。专栏逐 UP 显式订阅，与视频分开。保存视频或文章的稳定 ID、发布时间、规范链接、标题、简介及可用媒体。专栏列表发现不要求抓取全文，全文属于另行启用的增强；抓不到全文不阻塞卡片。观看入口支持直链或配置的播放器唤起方式，原始规范 URL 始终保留，不绑定特定跳转域名。

重叠回看与持久待处理队列共同补漏；单轮限额不能让高产来源长期饥饿。正常就绪项在各自源内按时间排队，失败空洞的继续/等待策略与 F06 一致。视频、文章及不同作者的故障隔离。摘要缺失则使用标题/简介/原文链接；封面失败发送文字。限流按 [网络合同](04-integrations.md#network) 处理。

<a id="f11"></a>
## F11 YouTube 订阅

按稳定 channel ID 订阅，支持白名单、黑名单、来源级目标覆盖、回看窗口及视频 ID 幂等。RSS、官方 API 或其他接入是适配器选择，应报告使用方式、配额与内容覆盖。

支持按时长过滤短视频。时长未知需明确采用保留、暂缓或已配置标题规则，不能伪造时长。初始兼容策略见迁移 profile。元数据补全失败保留可用内容；下载封面和摘要失败回落文字；迟到内容与积压仍可补入。

<a id="f12"></a>
## F12 长期机会、热点与重复话题

日报可提取长期机会、短期线索、失效信号与话题出现记录。保存来源、标题、内容、类别、链接、捕获时间、有效期、提及与状态。长期机会使用稳定身份合并；追踪参数不制造新机会。失效信号须可追溯，保留旧状态与变更原因。

同一处理批次重放不得重复增加提及次数或重复插入线索。原始输入事实与派生计数分开，批次失败能够恢复。活跃内容可进入后续摘要上下文；Markdown 清单是可重建视图。机会提取、持久化或视图失败时日报正文继续。

<a id="f13"></a>
## F13 成长片段与日卡

按所配置的群和日期挖掘成长片段，保留真实消息范围、发送人和本地原文切片。对模型给出的 ID、时长、数量、分数与引用逐项核验；金句须与原文一致。无可信引用的候选进入拒绝/复核状态。

支持历史挖掘、补录、待发队列、日配额、偏好日期及分数排序。部分分块失败不宣称整天完成。多个执行者不能领取同一片段，进程退出后的领取可恢复；已开始外部发送的领取不能因超时直接再发。

确定性 A 卡与模型 B 卡可比较；评审可采用独立模型，生成或评审失败回落 A 卡。成功后记录所发版本、配额与回执，不确定发送单独处理。来源即使被清理，已归档的切片仍可作为长期证据。

<a id="f14"></a>
## F14 成长反馈、周报与 rubric

收集指定操作者的反馈，按 ISO 周和配置时区汇总内容质量、队列及 A/B 表现。rubric 可生成修订建议，保存旧版本、采用的新版本及反馈来源；无效反馈不能覆盖规则。

反馈入站、被消费、规则修订与报告投递分别幂等；同一反馈不得在恢复后再次学习。同周确认送达后常规重跑只返回已有结果。预览不消费反馈，不改 rubric，不抢其他 bot 消费者 offset。正式生成但不发送可以产生草稿与候选规则，是否采用由明确应用命令决定。

<a id="f15"></a>
## F15 健康附录

从配置的 Health Auto Export 文件或等价适配器读取睡眠、活动等数据，生成文字摘要、可选卡片及缺口记录。区分零值、缺失、过期和不足基线，注明测量时间与比较窗口，不从缺失数据编造趋势。

可在日报运行时单次读取可用睡眠信息；没有新睡眠记录立即继续。健康源不可用时不阻塞日报。健康数据采用比一般日志更严格的访问与保留配置，卡片与文字可独立降级。

<a id="f16"></a>
## F16 知识索引与检索发布

保留本地归档、聊天导出、确认送达内容、订阅媒体和 Podcast4Bot 材料的收录。有效但未关联投递的材料可保留为 source_only，仅有元数据的记录明确标记 metadata，不能当作全文或已送达内容。机会库直接收录及跨访问范围过滤是新实现扩展，须单独验收，不作为旧索引已经具备的能力。稳定文档身份、原文 hash、出处、时间、访问范围与多个投递链接必须一起保存。相同 ID 对应冲突内容或错误来源时拒绝合并并报告。

支持扫描、增量构建、校验、查询、诊断、评测、影子运行、候选激活、小范围验证、发布、回滚和紧急关闭。构建成功只产生候选代际；普通查询受发布状态控制。换 embedding、tokenizer、维度或分块规则创建新代际，不能混用向量。

搜索结果含文档定位、出处和可访问状态，过滤后再向模型提供证据；跨聊天/话题权限不可串用。索引故障保留原档与已投递内容，不阻塞 F04/F06。影子结果与正式服务指标分开。

<a id="f17"></a>
## F17 意图反馈存储

记录 read、expand、switch、filter 等阅读意图，以及主题、模式、时间、操作者、文档关联和幂等键。原始事件可追加，主题视图可重建。相同幂等键与不同内容冲突时拒绝覆盖；重新分类另记事件。

无法关联已存在文档时保持 pending，不能伪造已确认来源。提供导入/查询/重建入口。聊天助手自动采集与主动推送属于后续接入，当前只要求实现事件合同与适配接口。

<a id="f18"></a>
## F18 调度与任务控制

支持指定时区的每日/每周计划、间隔、抖动、补跑、暂停和防重入。每个任务有身份、触发原因、计划版本及运行状态。错过触发后按已声明策略补跑，不能无限累计重复日任务。

区分正常完成、部分完成、无内容、失败和发送待确认。成功条件由管线合同决定，失败不能推进“已成功”的周期。配置变更避开在途任务或明确等待/取消；任务取消不能撤销已发消息。跨主机一个生产投递范围只能有一个有效写入者。保持宿主调度器或改常驻调度器均可。

<a id="f19"></a>
## F19 观测、告警与诊断

按 run、来源、业务日期、目标、阶段和 attempt 查询状态、耗时、失败原因、降级、积压、预算及回执。能回答“没有新内容、源未采集、被过滤、模型失败、尚未投递、结果待确认”中的哪一种。

告警脱敏、合并重复故障并在恢复时闭环；告警服务失败不递归触发告警风暴。诊断默认只读，不启动模型或修改生产数据。版本、配置版本和实际写入者可现场查询，不能靠 README 固定数量判断运行状态。

<a id="f20"></a>
## F20 跨项目账本与数据交换

维护内容送达与媒体 URL 映射两类独立合同。Podcast4Bot 可以从 Telegram 目标消息追溯视频/文章；外部确认 caption 可进入同事件候选。每一事实域有明确权威写源，镜像只读并经过 schema、hash、时效和冲突校验。

源快照损坏、缩水、历史被改或过期时保留上一个有效快照并降级，不覆盖事实源，不错误抑制新消息。对外旧格式在兼容期继续导出，具体字段见 [外部接口](04-integrations.md#ledgers)。

<a id="f21"></a>
## F21 CLI 与操作网页

所有运维能力首先有可脚本调用的命令与结构化结果。网页提供来源、运行、投递复核、归档搜索、调度和配置入口；优先只读，再开放操作。错误、空状态、过期状态、加载与部分失败要可辨认。完整交互合同见 [操作界面](06-interfaces.md)。

网页不可直接编辑事实数据库或自行推算业务终态；所有写操作走与 CLI 一致的应用合同。浏览器刷新、双击或网络重试不得执行两次。

<a id="f22"></a>
## F22 数据维护与迁移

支持有清单和校验和的导出、恢复、状态对账、限域回填、索引重建、保留清理及来源停用。清理只影响满足保留规则且无未完成引用的数据，提供预览与统计。历史失效或无法补回的来源明确记录。

按照 [迁移与回滚](08-migration.md) 保留原始事实、失败记录、人工结论和冻结快照。重复导入幂等，冲突隔离；新系统切换后产生的回执和反馈必须带回回滚系统，不能简单恢复旧数据库备份。

<a id="f23"></a>
## F23 频道特定信号监控

保留现有“商品标识加补货/可用性信号”的确定性提醒能力，规则、来源与目标可配置。首次建立基线避免重播历史，允许显式配置很短的启动追赶窗口。编辑、重连、重复事件和库存为零等否定信息需有确定行为。

规则判断不依赖 LLM，错误不影响主频道链路。不固定某一家频道、商品或常驻运行环境。提醒仍遵守 F07 的投递合同，不包含购买或账户操作。

<a id="f24"></a>
## F24 研究与遗留工具

保留固定输入/保存模型输出的评测、token 与长度统计、发送切片统计及结果导出能力，默认不真实投递。实验文件与生产状态分目录。

旧图床、脚本文件名、兼容 flag 和一次性迁移器按 [决策登记](10-decisions.md) 决定保留、替代或退役；有其他消费者的命令先提供过渡适配。实验收益不得写成生产收益。
