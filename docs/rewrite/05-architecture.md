# 架构选择与设计空间

## 必须满足的边界

新实现分清采集、内容处理、投递、状态存储、查询视图和操作接口。它们可以在一个进程中，也可以通过任务队列连接。边界依据业务责任与故障隔离，目录和服务数不作验收项。

业务决策在应用层处理；来源与目标适配器负责平台协议；存储层提供原子操作和版本迁移；CLI/网页共用应用命令。格式渲染不能写送达状态，采集器不能擅自调用目标发送，网页不能直接改数据库。

## 建议起点

采用模块化单体和有界任务执行，先跑通一个来源到一个目标。把需要平台运行环境的采集器放在可访问数据的机器，允许通过版本化输入导出或本地代理接入。重负载工作可后续独立执行。

这是实现建议。若独立伸缩、远程采集或故障隔离有明确证据，可采用多服务；对应方案必须增加队列持久性、协议兼容、重试、任务所有权和可观测性的验收。不要仅按“采集/模型/数据库/前端”四个名词拆成四套服务。

## 技术选择表

| 选择 | 适用条件与需要证明的事项 |
|---|---|
| Python、TypeScript、Go 或其他语言 | 所需适配器、部署平台、并发与打包可用；选择一种主要应用语言，额外 runtime 有直接理由 |
| SQLite | 每个事实库的写入者集中在一个主机、并发写压力有界；通过事务、锁等待、备份和恢复测试 |
| PostgreSQL 或其他服务数据库 | 多进程/多节点写入需求或运维体系需要；承担服务安装、升级、备份、连接与权限运维 |
| 内嵌任务表/本地持久队列 | 当前积压、定时和恢复可满足；进程崩溃后可恢复已接受任务 |
| 独立 broker | 已测出的吞吐或隔离需求值得增加组件；重复投递、确认顺序与死信仍由合同约束 |
| SQL/全文检索/本地向量 | 满足冻结语料的召回、权限与时延要求即可 |
| 独立向量服务 | 规模、过滤或并发负载证明必要；需要原文到向量代际追溯、备份与重建方案 |
| 服务端页面或前端框架 | 都要满足 F21 的任务、状态与可访问性；首屏无需加载整个历史内容 |
| cron/launchd 或常驻调度器 | 保留时区、错过触发、防重入、任务租约和可查询计划；不能让两套调度同时送同一范围 |

SQLite WAL 使用同主机共享内存，不能把同一个 WAL 库放到网络文件系统供跨机进程读写。跨主机同步用协议或一致导出。依据：[SQLite WAL](https://sqlite.org/wal.html)。选择服务数据库也不会自动解决 Telegram 的发送歧义。

## 逻辑存储

持久事实至少覆盖原始输入及覆盖范围、内容版本、投递计划/尝试/回执、筛选决定、反馈、机会生命周期、任务所有权及配置版本。核心状态转换需要原子性或等价的可恢复日志协议。

全文索引、向量、Markdown 导出、缓存、缩略图和统计聚合可重建。它们有独立失败与修复状态。代码不能每个候选都重新加载全部历史；查询应有分页、索引或预算边界。

库是否合并、采用多少表由事务关系决定。不要把“一切放同一库”或“每模块单独一库”写成原则。跨库没有共同事务的操作须显式处理部分成功。身份唯一约束、任务领取、反馈幂等、决定与终态一致性必须由存储原语保证，不能只用进程内集合。

## 并发与背压

独立来源可以并行；同一个有状态客户端/session 由唯一访问协调者或上游支持的并发方式使用。外部服务并发上限、抓取页大小、附件大小、模型预算与任务队列容量全部有配置和观测。

当处理能力不足，保留待处理输入和覆盖缺口，暂停继续扩张或降低低优先级任务；不能静默丢弃。实时正文、回执修复、人工复核、后台回填分别有调度优先级。长模型请求超时不能永久占住其他管线。

## 配置与依赖

主程序能在空环境运行合成模式，无 Telegram 或 LLM 密钥也能检查配置结构和运行隔离验收。按能力校验必需依赖。部署 profile 覆盖模型、出口、路径和启用项；代码默认值不复制到多份文档。

新实现提供一个可查询、可校验、可导出的配置定义来源，生成示例和字段说明。模板只保留解释用途、约束和副作用的注释。机器路径、实时模型列表与部署版本由诊断命令查询。

## 演进规则

先使合同可测，再优化热点。增加缓存需要失效策略与外部修改可见性测试；修改队列和存储需恢复演练；替换模型需相同冻结集评价。对外协议变化采取版本化和有期限兼容导出。做出决定时使用 [ADR 模板](templates/adr.md)，记录替代方案、理由、证据和重新评估条件。
