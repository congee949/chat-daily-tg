# 质量、性能与资源预算

## 正确性先于加速

固定输入上比较来源身份、覆盖区间、过滤决定、主内容、来源链接、相册成员、目标和终态。生成文本可以不同，但不得丢掉事实条件、来源或新增信息。性能报告同时展示完整性与故障结果。

旧报告中的微基准只对应其版本、机器和输入；新项目重新建立基线。所有数值必须标明“目标”“实测”或“未测”，使用 [基准模板](templates/benchmark.json)。

## 可重现负载

以下为开发用合成负载，不是现网规模调查。种子、生成器版本、输入 hash、硬件、OS、运行时、并发与出口条件一起固定。

| profile | 输入规模 | 要观察的问题 |
|---|---|---|
| smoke | 3 个来源、60 条消息、一个相册、一个故障来源 | 从空环境运行、语义正确、恢复 |
| nominal | 50 个来源，24 小时 10,000 条新消息；100,000 条历史记录；500 条待投递内容 | 日常处理、去重、检索、分页与队列延迟 |
| backlog | nominal 的 7 天积压，混合乱序、编辑、删除、分页和过期附件 | 不跳洞、公平性、内存和排空速度 |
| history | 1,000,000 条历史记录；新消息量与 nominal 相同 | 增量路径不能退化为每条扫描全史 |
| degraded | nominal 加模型长延迟、429、源离线、写失败和响应丢失 | 正文退路、预算、故障隔离和恢复 |

消息长度和媒体比例由 [workload.json](contracts/workload.json) 固定。合成集要含中文、英文、代码、链接及长 caption。测模型质量另使用冻结的、具备合法使用范围的真实或人工编写样本，不把随机文本当摘要质量证据。

## 时间与资源测量

分段计时包括 source_fetch、queue_wait、normalize/filter、generate、enrich、send_wait/send、commit 和 repair。端到端从任务接受开始，到主内容 confirmed 或明确待确认/失败结束。统计所有尝试及失败率，不能只报告成功快请求。

本地路径进行一次预热后至少 30 次独立采样，报告 p50/p95、范围和样本数；需评估尾部时增加样本并说明 p99 的计算方法与稳定性。冷启动与热运行分开，磁盘缓存、连接复用、模型加载和网络延迟单列。第三方限流/冷启动时间保留在端到端结果中，也单列便于归因。

报告 CPU 时间、峰值 RSS、进程/线程数、文件与网络句柄、最大队列长度、最老任务年龄、写入量、模型调用/token/成本及失败重试。成本不可得时标记 unknown，不能填 0。

## 初始设计目标

这些是可调整的开发目标；在 M0 固定选定 profile、参考机器与预算，通过 [D04](10-decisions.md#d04) 登记。实测不能倒推修改目标来变成通过。

| 指标 | 初始目标 |
|---|---|
| nominal 下本地列表/详情查询 | p95 ≤ 1 秒，不包含外部网络 |
| history 下权限过滤后的文本搜索 | p95 ≤ 2 秒；向量模型时间另列 |
| 队列与内存 | 队列容量和 worker 有硬上限；压力期间无无界增长，恢复后回到稳定基线 |
| 独立来源隔离 | 单来源超时只消耗自己的预算，其他已就绪任务能继续执行 |
| 积压恢复 | 在同一资源预算下净处理能力高于新到达率；给出预计排空时间与实测误差 |
| 状态恢复 | 重启后有界恢复 pending 和领取状态，confirmed 不自动重发，ambiguous 保留待核验 |

完整日报受外部模型影响，不承诺脱离部署条件的固定“几秒完成”。M1 的真实链路形成 fetch/model/send 分段基线后，在生产接管前固定该 profile 的端到端 p95、允许积压时间及资源上限。

## 内容与去重质量

摘要用固定样本评估覆盖、事实支持、来源可回溯、条件/时间保留、冗余和可读性。记录模型版本、提示版本和评审方法；人工复审保留理由。A/B 卡质量与去重误杀分别衡量。

去重样本按来源、同链接新信息、不同图片、同事件不同阶段、转译/转述、否定与不确定结果分层。报告样本总数、有效人工标签数、冲突/不确定数、误抑制数、精确率/召回相关分母及置信范围。不得只报总体准确率掩盖少数严重误杀。发布最低门槛从 [兼容 profile](08-migration.md#compatibility-profile) 继承；阈值重选还需对应版本的冻结评测。

## 可靠性与保留

在可能产生外部副作用的边界注入崩溃：领取后、发请求前、服务端接收后、回执落盘前、正文后可选媒体前、同步替换中。结果应满足 AT 用例，而非只检查没有异常。

数据保留区分原始聊天/健康数据、投递与抑制证据、模型派生物、媒体缓存、日志和备份。每类有保留期、访问范围、删除预览和不可删除的在途引用。默认不删除既有原始材料；初始保留策略在 [D07](10-decisions.md#d07) 定稿。

## 安全与隐私

真实消息只发送给配置启用且用途匹配的模型/平台。内容中的指令、链接与模型返回都视为数据，不能改变目标路由、读取任意文件或获取凭据。测试验证日志、错误、导出和网页均无秘密。私有来源权限变化要影响搜索和未来投递，已有归档的处置按保留政策执行。

备份必须能恢复，不能只报告文件已生成。恢复点目标和恢复时间目标随部署 profile 指定，计入迁移演练。核心状态库迁移失败不得启动新写入者。
