# 决策登记

本文件记录尚未由实现或测量决定的取舍。建议可用于启动开发，只有标明完成并附证据的决定才可作为生产接管依据。使用 [ADR 模板](templates/adr.md) 保存详细理由，避免在各文档重复说明。

<a id="d01"></a>
## D01 所有投递持久记录均不可写

状态：生产策略待定。旧系统倾向正文优先；新系统增加核心记录和紧急持久日志，以减少不可恢复发送。

开发先实现主库失败时紧急日志接管。两者均失败时提供两个明确策略：暂停该投递并告警；或允许受控的 best-effort 发送，记录内存状态、告警，并在进程重启后隔离受影响范围等待对账。后者无法保证跨进程去重，不能标记持久确认。建议生产采用前者；改变既有正文优先偏好须在接管前明确决定。

不因这个选择停止其他独立来源采集与已具备记录的任务。验收 AT14 验证两种配置的可观察结果。

## D02 语言、框架、存储与部署

状态：M0 决定。建议先模块化单体、集中持久状态及有限 worker。数据库选择基于实际写入拓扑和负载；页面方案基于 F21，模型按能力接入。落盘 ADR 至少比较一种更简单替代方案，附空环境运行和故障测试。

生产主机可以改变；接管时必须接续原有来源访问、出口、单写者、反馈入口与外部消费者。不能为了复刻机器名称保留不必要跨机复杂性。

## D03 功能退出与新增范围

状态：默认保留全部现有能力。F16/F17 继续门控，F23 可配置，F24 保留评测/导出而非所有旧脚本。F21 完整控制台是新目标，CLI 和只读网页先行。

任何功能退役要在覆盖表增加具体理由、替代方式、数据处置和范围决定；不能因为 README 没提到就删掉。是否为已有调用者提供兼容 CLI，在迁移清单中确定。

<a id="d04"></a>
## D04 部署负载与服务目标

状态：M0 固定合成基线，M1 固定真实链路目标，M4 前完成验收。开发使用 [质量文档](07-quality.md) 的初始目标；参考硬件、每轮/每日模型预算、端到端延迟、可接受积压及恢复时间随 profile 记录。

若真实负载与合成负载不同，新增 profile 而不是修改已测输入。调整目标需解释实际约束，保留此前失败结果。

## D05 去重策略与模型替换

状态：report 为安全起点，人工发布条件保持。确定性 URL-first、语义阈值、authority 优先级与媒体规则按来源 profile 配置。不能以新架构更可靠为由自动提高抑制强度。

替换 Jev、LLM、embedding 或重排器需要能力适配、成本/延迟、人工质量和退化测试。模型品牌及 reasoning effort 可选，但新版本不得继承不适用的校准批准。

## D06 新内容的编辑与更正

状态：推荐方案可用于开发。源编辑保存修订；尚无外部尝试的计划可以原子取消并按最新合格修订重建。任何部件进入 sending 后原计划固定，不能替换尾部文字；已发送内容不默认重发。明显错误可由显式更正命令关联原消息；自动更正规则若要启用，另做范围、时限与测试。

同一源投向新目标默认只处理启用后的内容；历史回放必须单独指定。防止配置更改意外重播全史。

<a id="d07"></a>
## D07 隐私、保留与恢复窗口

状态：生产 profile 待定。开发默认保留导入原档及证据，缓存可在隔离样例中测试清理。真实聊天、健康数据、发送证据、日志、备份分别设保留期与访问范围。

生产接管前明确备份频率、最大可接受状态损失、恢复时间、回滚窗口、旧数据处置及搜索访问规则。全新文件夹本身不构成旧数据删除授权。

## D08 网页写操作发布

状态：M3 只读，M5 逐项开放。认证可使用现有可信入口，也可用应用自身单操作者登录；禁止默认公网无认证。写操作上线前完成权限、幂等、冲突、CSRF（采用 cookie 会话时）及高影响操作预览测试。
