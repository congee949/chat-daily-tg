# 实现启动说明

在一个新的代码目录实现 ChatDaily。输入为本规格包；不读取、导入或复制旧项目实现。迁移适配器依据 [旧数据合同](08-migration.md) 和合法取得的导出样本开发。

先提交到工作区的产物是：架构决策、功能到模块的映射、可运行的合成来源到模拟投递路径、隔离的状态存储和故障测试。首次技术选型可按 [架构选择](05-architecture.md) 的建议起步；采用其他方案时写明它解决的具体约束及运维代价。

按 [产品范围的交付顺序](01-product.md#milestones) 推进。每个阶段都保留可运行结果，逐步增加来源和能力。完成的标准是关联 AT 用例有可复查产物，覆盖表中的能力有实现或明确的范围决定。

最先验证：同一源重放、相册、部分发送、响应丢失、进程崩溃、抓取空洞、模型故障和路由变更。性能测试同时核对内容与状态，不能靠漏抓、少发、少归档获得加速。

把用户可见操作做成统一的应用命令合同，先由 CLI 调用。网页按 [操作界面](06-interfaces.md) 分阶段增加，直接复用同一合同。模型、Telegram、源平台、文件系统和调度器通过可替换适配器接入。

生产接入前完成配置清单、真实测试回执、迁移演练、切换单写者和回滚演练。保留原系统运行至切换条件满足。重写阶段不得并行向同一生产目标投递。
